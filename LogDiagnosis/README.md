# LogDiagnosis

主界面支持选择源码分支，工程 code_branches 为各分支保存源码、板卡配置清单和独立关系库。当前分支为 MSCP_MSCP。加入新分支的步骤见 [分支使用说明](分支使用说明.md)。

AI 分析每次加载 [crash-log-rca/SKILL.md](skills/crash-log-rca/SKILL.md)，按其中的周期切段、五层下钻、源码定位、对照和报告模板进行分析。修改该文件后，下次点击“AI 分析”即加载更新。“AI 分析依据”的 `analysis_skill` 记录文件哈希，`rca_trace` 提供最近已观测周期的有序原始日志和来源行号，截取范围及资源限制随证据记录。

最新版技能要求自检逐项穷举，核对表覆盖正常项和所有异常项，并逐项标明致宕、伴生或待核实。软件补充 `source_evidence.self_check_review`，按有序日志检索自检编码的源码位置与当前板卡自检文件正文。结论先简明列出各个有证据的问题，核对表保留完整条目，重复事实集中表述。

主界面只有一个日志分析页面，日常操作为：

1. 拖入或浏览选择文件名含 ATP、IPB、OPB 或 SPB 的原始暗文日志，板卡自动识别，并使用工程 board_config 对应板卡目录中的配置头文件。
2. 点击“日志解析”，只解析并生成 CSV，不调用 DeepSeek；结果区域显示生成文件的路径。
3. 点击“AI 分析”，复用本次 CSV，与正常基线比较、检索源码关系库并调用 DeepSeek，在同页显示分析结果。

也可直接拖入或通过“浏览”多选已解析的 CSV，点击“AI 分析”，无需再次解析或配置字典。
同一份日志生成多个 CSV 时请一次全部选择；原始日志与 CSV 不能混合导入。
CSV 模式下“日志解析”按钮禁用，切回原始日志后恢复；导入文件本身不会请求 AI。
支持正常周期 CSV 和 DownLog 无周期宕机 CSV，文件内容和分段归属会在本地比较时校验。

CSV 读取自动兼容五列、带板卡/周期列的扩展表头、带时间戳的格式，以及旧版“七列表头、五列事件”导出。
统一按表头或实际事件布局读取；支持 GB18030、UTF-8/BOM、UTF-16/BOM、标准 CSV 引号和旧导出描述中的字面引号。
分析、正常参照、基线建立和故障入库共用读取规则，不改写用户文件；无周期日志始终按事件顺序处理。

“查看过程与依据”默认收起，可展开查看处理过程、基线差异和实际交给 AI 的证据。
只解析日志时需要原始 PLFM 字典，字典路径按板卡记忆；AI 分析需要 API Key，对应板卡正常基线用于数值对照。没有基线时仍可根据明确失败记录与板卡专用源码分析，并说明缺少正常参照。
API Key 继续保存在当前 Windows 用户的凭据管理器，可随时保存、替换或清除。

## 设置与管理

- “设置”：本板卡字典、正常基线、源码关系库、可选日志软件版本、应用日志开关、DeepSeek 模型、API Key 和连接测试。手动板卡选择已移除，混板卡日志会被拒绝。
- “基线与样本管理”：保留正常基线建立和宕机样本导入；支持多选/拖入同一日志的多个 CSV。
- 建立正常基线成功后，会自动把该数据库设为日常分析使用的基线。
- 原因标签可以留空；解析或 AI 分析不会自动把日志加入正常基线或故障样本库。
- 正常基线建立、故障样本入库都在后台执行，页面显示阶段进度和已处理事件数，可取消任务。
- 管理窗口可以关闭后重新打开查看后台进度；任务期间可切换标签、查看结果，同一时间只执行一个管理任务。
- 管理任务期间暂不能启动新的分析，以避免读取正在重建的基线；其他已有结果仍可查看。
- 取消或失败时回滚当前事务，旧基线和已有故障样本不变；开始最终提交后等待保存结束。
- 关闭主程序时先请求取消后台任务，等待回滚或已开始的提交结束后自动退出，等待期间保持界面响应。

## 自动处理与错误恢复

- 两个按钮互相独立：解析完成只保留本次 CSV，只有用户点击“AI 分析”才执行比较和 DeepSeek 请求。
- “AI 分析”在解析完成或直接导入 CSV 后启用；原始日志模式下更换日志、字典、板卡或解析选项后需重新解析，防止复用旧结果。直接导入 CSV 不依赖字典或解析选项。
- AI 失败或取消后可直接重试 AI，无需重复解析；基线、模型、日志版本改变也不需要重新解析。
- 新流程每次在桌面 LogDiagnosisData/ParsedLogs 下创建独立工作目录，保留原始日志副本和此次 CSV，避免旧分段混入。
- 解析失败或停止时不启用 AI；解析成功后若基线不匹配、比较失败或网络失败，会保留已生成的 CSV，主界面显示原因。
- 支持停止分析。若解析核心正在写文件，会等当前文件写完后停止，不再继续请求 AI。
- DeepSeek 单次请求超过 120 秒时结束并提示超时。
- 软件退出会阻止剩余步骤继续请求 AI。

## 本地比较与 AI 分析

OPB 真正周期号只取自事件编码 `0x0A1A` 的四字节原始值（原始值为空时读取有效解析值）。
旧 CSV 的 `Cycle Num` 行和“周期号”列仅为冗余，保留原文件但不参与划分、连续性检查或故障判断；新解析结果不再生成 `Cycle Num`。
第一条 `0x0A1A` 之前的事件保留为周期未知；完全没有该编码时不补造周期。
宕机事件序列即使包含真实周期，也保留事件顺序与变量值比较，不假定具备完整周期/数据包上下文。
周期计数器增长不作为数值超出正常范围的候选异常。旧规则建立的正常基线需重新建立，避免混用统计口径。

当前候选规则为：基线未见编码、内部周期事件次数超过 P99、基线稳定编码缺失、数值超出基线观测范围。
对于 DownLog 等没有周期号的宕机 CSV，会自动使用变量值比较模式：按事件顺序保存和分析，不要求或伪造周期号。
该模式比较同一编码的原始值、解析值及正常数值范围，并保留变量名称、事件序号和明确失败记录供 DeepSeek 定位核查对象。
“错误”打印等级单独保留为背景，只有解析值明确表示失败时才进入明确失败列表。AI 报告按独立问题合并说明，取消固定五组的输出要求，背景变量摘要用于交叉验证并按需引用。
变量参照优先从基线记录的完整正常源 CSV（含上电过程）读取；源文件大小或修改时间改变、缺失或无法完整读取时，回退到已有稳态统计并注明限制。
版本和 MD5 的跨日志差异作为背景信息；没有正常参照的变量不直接判坏，未知位定义和单位不会自动补写。
连续数值处于正常范围内时，不因未出现过完全相同的数值而直接判为异常；状态类变量可额外比较已观测的离散取值。
宕机事件序列模式跳过每周期次数、缺失和周期/包连续性规则。快照事件单独保存事件序号；出现 `0x0A1A` 时记录真实周期范围，否则周期范围保持 NULL。数据库回读也只从 `0x0A1A` 重建周期，不信任旧周期列。
周期/包序号不连续单独列为数据质量 UNKNOWN。首尾周期、周期跳变两侧及包上下文不完整的周期跳过次数/缺失规则。
已知软件版本不匹配时停止；版本缺失时在证据中注明兼容性 UNKNOWN。
相同规则和编码合并为一组，最多传递 80 组并记录省略数量，每组保留 3 个周期示例。

证据包含编码、周期、基线值、实际值和限制说明。点击“AI 分析”后，会自动查询设置页指定的源码关系库，加入相关源码片段、相对路径、行号和限量调用关系，再发送给 DeepSeek。源码版本未知或不匹配时会注明；关系库不可用时会提示并继续日志分析。可在“AI 分析依据”中查看实际发送的 JSON，详细说明见 [源码关系库说明](source_relations/README.md)。
AI 必须区分已确认事实、候选解释和未知信息，并引用证据编号。基线范围不是设备安全范围，P99 不是故障硬阈值；
未命中规则不表示正常，候选命中也不等于确定宕机原因。尚无真实宕机样本验证诊断准确率。

正常基线目前支持同一包日志的多个 CSV；多包独立日志的合并训练仍待实现。
保留命令行离线 CSV 比较入口：

```text
LogDiagnosis.exe --diagnose-opb baseline.db incident-evidence.json capture.txt1.csv capture.txt2.csv
```

## 宕机 CSV 入库

“基线与样本管理 → 宕机样本 → 添加解析 CSV → 添加到故障样本库”。
支持 DownLog 解析后的无周期 CSV（例如 `.txt宕机.csv`），无需补周期号或改成正常日志格式。
同一次原始日志生成多个 CSV 时一起选择，作为同一次故障事件保存；已知原因标签可以留空。
故障样本库用于保存事件及标签，导入不会覆盖正常基线，也不等同于自动训练 DeepSeek 或更新诊断阈值。


## 验证

- tests/DiagnosisTests.pro：比较规则、分段衔接、边界、版本、取消、故障库读取等。
- tests/DiagnosisUiTests.pro：两按钮流程、无 Key 解析、缓存与输入绑定、解析失败、版本不符、停止、网络失败与不重复解析的重试。
- 后台任务回归还覆盖写库/提交前取消、异常回滚、数据库占用时界面响应、关闭窗口及取消后重试。
- 宕机快照回归覆盖数值比较、正常上电值参照、无参照处理、构建标识区分、无周期入库、旧库事务升级和完整一键流程。
- 默认使用临时夹具与模拟 DeepSeek，不请求线上服务；liveSeparateParseAndAi 显式启用时验证真实解析与线上返回。
- 测试夹具不进入正式基线或故障样本库。

## 构建

统一打开工程根目录的 `LogDiagnosis.pro` 构建和运行。日志解析核心保存在工程内的 `NewAnalysis/`，主程序、插件和测试均引用此目录。发布程序为 `bin/LogDiagnosis.exe`。

Qt 模块：widgets、sql、network、concurrent；测试另需 testlib。

```text
qmake LogDiagnosis.pro
mingw32-make
```
