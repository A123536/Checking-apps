# 源码函数调用关系库与查询插件 v1.2

## 使用

运行 `../bin/LogDiagnosis.exe`，导入文件名包含 ATP、IPB、OPB 或 SPB 的日志。界面自动显示识别结果，顶部“源码关系查询”打开对应板卡库。

关系库分别为 `MSCP_MSCP.ATP.sqlite`、`MSCP_MSCP.IPB.sqlite`、`MSCP_MSCP.OPB.sqlite`、`MSCP_MSCP.SPB.sqlite`。配置头中的 `APP_BOARD_NAME` 与主宏确认了映射，ATP 启用 `IS_5728_MCP`，IPB 启用 `IS_570_IPB`，OPB 启用 `IS_570_OPB`，SPB 启用 `IS_570_SIG`。函数内部的条件编译分支也在建库时筛选，行号保留。同名函数与日志编码具有板卡专属上下文。

- 函数名支持包含匹配，例如 `Plat_Main`、`MSW_State_mainlogic`。
- 日志查询支持十六进制、十进制编码及宏名，例如 `0x0A1A`、`2586`、`LOGTYPE_NEWCYCLE`。
- “解析问题”可按问题类别、缺失头文件名或源文件路径检索诊断记录。
- 选择结果后查看调用者或被调用者，深度为 1 至 5 层。调用树最多显示 300 个节点，递归路径有标记。
- 点击树节点可定位调用点。右侧显示按当前板卡宏筛选的源码快照及原行号。
- “重建关系库”选择源码目录并输入版本标记。取消和失败会保留已有数据库。数据库有读者锁定时，替换可能失败，请关闭其他数据库工具后重试。
- 每次重建生成一个新快照并替换所选数据库。保留历史版本时，请选择另一个输出数据库文件。

## 命令行建库

部署的建库工具自带 Python 运行时及解析依赖，可以独立使用。

```powershell
& .\bin\source_relations\SourceIndexer.exe --source 'C:\path\to\MSCP_MSCP' --output '.\bin\source_relations\MSCP_MSCP.sqlite' --all-boards --version '你的软件版本'
```

也可安装 `requirements.txt` 依赖后运行 `index_source.py`。`--all-boards` 构建四份独立库，`--board OPB` 等参数构建单板卡库。`--profiles` 可指定四板卡宏配置 JSON。已部署的独立工具优先读取同目录 `board_profiles.json`，界面重建按钮会重建四板卡库。

`board_profiles.json` 按板卡索引桌面 `ATP`、`IPB`、`OPB`、`SPB` 文件夹中的 `PROJECT_OR_BOARD_PTCL.h`，读取实际的主宏、监控、多线程、自检、日志及周期配置。工具预载所选头文件，再沿本地 include 链求值，未定义宏按 C 预处理规则处理。主宏必须与板卡标识一致，否则建库失败。

每份库记录配置头及依赖的哈希、实际宏快照和来源。每次 AI 查询先校验配置文件，发生变化时在后台自动重建该板卡库。配置目录的副本随工具保存于 `config/`，原桌面文件优先使用。按用户确认，ATP 引用的 `integrationconfig.h` 不参与本次分析，在 profile 的 `ignored_includes` 中记录，ATP 使用已提供主头文件中的板卡与功能开关。

建库采用同目录唯一临时文件、完整事务、数据库完整性校验和原子替换。`--cancel-file` 指定一个取消标记路径，工具发现标记后回滚并移除自己的临时数据库。强制结束进程或断电可能留下 `.building` 临时文件，已有完整关系库仍保留。

## 数据结构

数据库 `PRAGMA user_version=1`，`metadata.format=logdiagnosis-source-relations`。

| 表 | 内容 |
| --- | --- |
| metadata | 快照 UUID、源码哈希、源码目录、版本标签、解析器版本、统计 |
| files | 原文件 SHA-256、编码、路径、UTF-8 源码文本、语法错误标记 |
| functions | 函数签名、文件、起止行、static 作用域、编译条件、语法错误标记 |
| calls | 调用点、表达式、所属函数、位置、种类、编译条件 |
| edges | 调用点到目标函数的关系、解析类型、推导依据 |
| bindings | 结构体初始化表中的字段与函数地址绑定及来源 |
| macros | 对象宏、函数宏、表达式、编译条件 |
| log_sites | 普通／特殊暗日志和异常暗日志的编码、数据和长度表达式 |
| diagnostics | 缺失的外部 include、语法恢复区域、编码替换记录 |

`call_details` 视图合并调用点、调用者和源文件，便于 SQL 查询。

`source_direct` 表示按源码名称和作用域绑定的直接调用。`candidate` 表示间接调用或存在多个定义时的候选。`macro` 表示函数宏调用，尚未展开。`external` 表示发现声明但缺少定义。`unresolved` 表示目标尚未解析。

结构体接口表根据声明类型及字段位置／指定初始化字段建立候选关系。局部函数指针支持追踪赋值，以及返回函数指针的辅助函数。类型转换歧义、局部参数遮蔽、文件内 static 同名函数均有专门处理。

## 当前范围

本版提供板卡宏筛选后的源码语法级索引。已知条件求值后移除不生效分支，匹配板卡内的未确认功能分支保留为候选。函数宏内部调用、完整指针分析、运行时注册回调、跨函数参数传递和 SDK 外部函数仍有未解析范围。间接调用候选集合也可能不完整。

解析器在缺失类型和编译器扩展附近可能恢复语法，必须结合 `has_errors` 与 `diagnostics` 核查。源码哈希用于识别快照，版本和板型标签由使用者提供。当前库的版本为目录快照标记，尚未验证它与某个运行固件一致。

## AI 分析自动关联

点击主窗口“AI 分析”后，后台先完成日志／基线诊断，再通过插件只读查询设置页指定的源码关系库，最后把合并证据交给 DeepSeek。无需先打开查询窗口。默认复用已部署的 MSCP_MSCP 关系库，也可在分析设置中切换。

AI 流程按明确失败与异常候选涉及的编码检索源码，避免正常编码消耗源码检索范围。每次最多查询 12 个编码，发送 12 个源码记录点，源码证据上限为 48,000 UTF-8 字节。上下游关系最多两层，代码片段与关系均限量截取。这些是源码检索的资源限制，报告按实际证据组织独立问题。

自检穷举使用独立的 `self_check_review`。它检查 `rca_trace` 中所有已观测编码，收集正常与异常自检项的源位置，并附对应板卡自检源文件及头文件正文，保留原行号。自检条目覆盖范围由已观测日志决定，源码正文预算为 128,000 字节，截取及未命中代码会显式记录。关键源码与自检补充的合计预算为 176,000 字节。

报告流程及格式由项目 `skills/crash-log-rca/SKILL.md` 管理，按周期切段、五层下钻、源码定位和对照组织。重复证据集中表述，独立问题按实际证据保留。候选变量单独提供比较，其余变量整理为 `supporting_context_variables` 背景摘要，用于交叉验证。`rca_trace` 保留最近已观测周期及可用前置上下文的有序事件、原始字节、解析值和来源行号，最多 2,000 条／160,000 UTF-8 字节，超出时标记截取情况。

错误级别的打印与明确失败状态分别记录。只有解析值明确表示失败、不通过或 failed 的记录进入 `explicit_failures`。错误级别数值的实际差异仍按正常观测范围比较，不因打印级别直接变成失败结论。

发送的 `source_evidence` 包含快照标识、源码哈希、版本／板型标签比较、源码相对路径、行号、日志变量表达式、附近代码、函数开头和上下游调用关系。记录带 `SRC001` 等引用编号，并关联日志的证据编号或事件序号。源码片段会随请求发送给所配置的 DeepSeek 服务。可在主窗口“AI 分析依据”中查看实际发送的 JSON。

当前源码与运行固件的完整对应关系尚未核实，因此检索结果标记 `reference_only`。板卡以文件名识别结果与专用库元数据校验，宏配置及未确认宏随证据发送。版本标签相同只标记 `label_match`，不同标记 `mismatch`，未提供则标记 `UNKNOWN`。关系库不可用、插件缺失或编码未命中时，会明确记录原因并继续日志分析。

手动板卡选择已移除。混板卡输入、名称含多个板卡标识、CSV 板卡列与文件名不一致时阻止本次分析。正常基线维护保留，并按板卡保存配置与独立数据库，阻止覆盖其他板卡基线。没有对应基线时，主界面仍可按明确失败记录和源码分析，并注明缺少数值参照。故障样本保留板卡字段和独立去重命名空间，兼容历史 OPB 数据。

插件接口已升级为 `SourceQueryInterface/2.0`，宿主与插件需一起更新。关闭当前软件后重新打开，加载更新后的 DLL。

## 构建与验证

宿主和 DLL 使用相同的 Qt 5.12.1／MinGW 7.3 64 位工具链。运行 `build.ps1` 可构建宿主、DLL 和独立建库程序。首次构建需下载 Python 依赖。部署目录保留现有 Qt 运行库及 SQLite 驱动。

索引器回归测试

```powershell
python -m unittest discover -s .\source_relations -p 'test_*.py' -v
```

查询插件测试工程为 `tests/SourceQueryTests.pro`。测试时设置 `SOURCE_RELATIONS_PLUGIN` 和 `SOURCE_RELATIONS_DATABASE` 为 DLL 与数据库绝对路径。

AI 使用四份板卡专用库，函数和调用数量随板卡及有效宏配置变化。精确计数、源码哈希及未确认宏以各库 `metadata` 为准。原始哈希按原始文件字节计算。

已验证六阶段调度 `pfunc_handle` 的六个候选目标、VotePolicy 虚表候选、0x0A1A 日志定位、同名 static 作用域、函数参数遮蔽、取消及失败保留旧库。插件测试覆盖动态加载、函数与日志查询、源码显示和无效数据库处理。

建库阶段验证了索引器 2 项测试、独立 EXE 取消、365 个源文件哈希及 SQLite 完整性。本次 AI 接入测试覆盖了按钮自动关联、周期日志与无周期快照、关系库失效回退、版本标签不匹配、证据体积限制和取消。AI 请求边界使用模拟客户端验证，真实联网测试按原设置跳过。

验证覆盖四板卡同名函数／同编码含义隔离、实际配置头文件、嵌套宏与本地 include、配置变化自动重建、板卡识别、混板卡拒绝、对应基线校验及无基线降级。ATP、IPB、SPB 尚需实际硬件日志补充验证，测试使用同一 PLFM 格式的板卡标识样本，并对 OPB 实际宕机 CSV 进行本地联调。
